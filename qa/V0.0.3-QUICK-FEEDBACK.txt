DIGS v0.0.3 QUICK FEEDBACK RUN
================================

Purpose
-------

This is the short, guided human-in-the-loop lane for a v0.0.3 candidate. A
keyboard/mouse pass takes about 20 minutes. Each controller transport adds
about 8 minutes. It does not replace the 88-checkpoint release pass.

Record only what you actually observe. A successful Linux test does not prove
Windows, macOS, a historical operating system, GPU acceleration, Bluetooth,
or vibration on hardware that was not used. Mark unavailable checks Blocked or
Not Run in qa/VOX_QA_FEEDBACK.xlsx.


0. IDENTIFY THE RUN (2 MINUTES)
--------------------------------

1. Extract the complete tester archive; do not copy bin/digs_demo by itself.
2. Copy qa/VOX_QA_FEEDBACK.xlsx to a new tester-named .xlsx file.
3. Fill the Environment sheet first. At minimum record:

     build ID and binary SHA-256       OS, architecture, CPU and power profile
     display resolution / refresh      SDL2 and audio backend/device
     controller model, GUID, transport and prompt family
     P1/P2 ownership and rope mode      haptics, Laptop and Dummy settings
     qualified cap result               seed, local players and bots

4. Use one visible seed for this entire run. Enable F1 diagnostics and capture
   one opening screenshot containing the seed, cap, tick and state hash.


1. NON-WINDOWED GATE (3-6 MINUTES)
-----------------------------------

From the extracted Linux x86-64 bundle run:

  ./smoke-test.sh
  ./bin/digs_demo --cap-self-test
  ./bin/digs_demo --audio-cadence-self-test
  ./bin/digs_demo --bark-self-test
  ./bin/digs_demo --haptic-self-test
  ./bin/digs_demo --load-self-test 600
  ./bin/vox_headless
  ./bin/digs_headless

The packaged smoke-test.sh also runs the haptic and full 600-tick deterministic
load checks. The load command must reproduce fired 46, explosions 26, effects
700, awake 7867, and hash f3924b81 without judging host speed. If 600 ticks are
temporarily too slow while diagnosing an active change, `--load-self-test 180`
is a reduced quick probe only and cannot pass VOX-QA-087. On the named
i7-10750H laptop bench only, run `--performance-self-test 600` or set
VOX_NAMED_BENCH_QUALIFY=1 for smoke-test.sh to attempt VOX-QA-088's strict
5/8/16.67 ms qualification. Optionally run ./benchmark.sh 60 for a quick
renderer sample. Keep every printed hash and exit status. Run smoke-test.sh
twice when investigating determinism;
the same frozen binary must print the same state/frame hashes. These commands
do not prove visible output, audible sound, controller behavior, or rumble.

Workbook IDs: VOX-QA-022 through 025, VOX-QA-075, VOX-QA-077, VOX-QA-086 and
VOX-QA-087. Add VOX-QA-088 only for a named-laptop qualification run.


2. KEYBOARD/MOUSE STABILITY AND COMBAT (8 MINUTES)
---------------------------------------------------

Start Full Works with one local miner and one bot. Wait out the five-second
spawn shield before judging damage.

1. Move, jump, and use short and long steampack burns. Cross a gap, reverse,
   glide, touch a slope and a ceiling, and verify there is no position jump.
2. Dig beside and below the miner. Remove support, trigger a collapse into the
   miner, and blast the same area repeatedly. A bounded push or one ordinary
   crush death is valid; a distant teleport is not.
3. Shoot the bot's head, torso and a limb with the Nail Gun and Shotgun, then
   use an explosive. Confirm visible hits reduce health exactly once and a
   legitimate death, gore/dismemberment and delayed respawn are distinct.
4. Repeat blasts against a wall and watch all debris settle or expire. Report
   any upward-moving column or one-cell needle tower with seed/tick/location.
5. Charge the Mining Rail with minus selected. Tap once, then fully charge
   through soft terrain toward the bot; repeat against stone/bedrock. Confirm
   tell, penetration/stop, anatomy result, recoil, afterimage and cooldown.
6. Use mouse-wheel zoom at the world edges and above lava. The hardware aim and
   single software reticle must agree; close zoom reveals more voxel/light
   detail; lava has one world position; no black frame is exposed.

Workbook IDs: VOX-QA-066 through 069, 073, 074, 082 and 085.


3. ROPE AND FEEDBACK (4 MINUTES)
--------------------------------

1. Test P1 Hold mode: cast to stable high material, swing, reel, reverse around
   a corner and release. Destroy the occupied anchor.
2. Switch P1 to Toggle and repeat. A miss must not auto-retry. The two modes
   must follow release versus a fresh press respectively.
3. After spawn protection ends, strike the bot with the hook head. The cast
   ends and the living target becomes exactly 1 HP; the cable is harmless.
   Repeat during a new spawn shield and confirm all damage/knockback is blocked.
4. Listen for hit/kill/rail/rope feedback and trigger C barks in several states.
   Speech bubbles and chip voice must agree, and ordinary mode must enforce the
   three-second local bark cooldown.

Workbook IDs: VOX-QA-068, 070 through 072, 077 and 083.


4. FRAME, AUDIO AND LAPTOP PARITY (3 MINUTES)
----------------------------------------------

1. In Options, inspect 15/30/60/90/120/144/Unlimited. Unsupported caps must be
   visibly gated. Test 15, one qualified high cap, and Unlimited briefly.
2. At each tested cap, navigate menus, zoom, fire, hear a bark and cause an
   explosion. Pitch, duration and cadence must not follow presentation FPS.
3. Set Master Volume 0 and confirm silence without a gameplay change.
4. Restart the recorded seed/input setup with Laptop Mode Off then On. Compare
   final state hashes. Presentation may change; terrain, damage, bots, effects
   simulation and the hash may not.

Workbook IDs: VOX-QA-061, 075 through 077 and 084 when doing the long soak.


5. CONTROLLER ADD-ON (8 MINUTES PER TRANSPORT)
-----------------------------------------------

Never infer one controller family or transport from another. Capture the SDL
name/GUID and prompt screenshot without recording a hardware serial number.

Logitech F310:

  - Unplug before moving the rear X/D switch; reconnect and calibrate centered.
  - Run once in X mode and once in D mode. Lock CONTROLLER, then test AUTO.
  - Check centered/noisy stick ownership, circular deadzone, diagonals, aim
    slowdown, one reticle, fire, rope, steampack, bark, pause and ZL/LT plus
    right-stick vertical zoom. Record whether D mode used raw fallback.

Nintendo Switch Pro Controller:

  - Run USB and Bluetooth as separate passes, including hotplug/reconnect.
  - Confirm Nintendo A/B/X/Y, L/R, ZL/ZR, Plus/Minus and stick-click prompts
    match the physical control used; do not accept Xbox-position labels.
  - Test Off/Low/Normal/Heavy vibration for own fire, rope hit, rail charge and
    release, nearby/distant explosion, damage, kill and crumble. Confirm Off is
    silent, levels are distinct, distant bot-only action does not vibrate, and
    no motor sticks. A driver that exposes no rumble is Blocked, not Pass.

Workbook IDs: VOX-QA-033, 034, 042, 043, 070, and 078 through 082.


6. TWO-PLAYER / BOT QUICK SOAK (5 MINUTES)
-------------------------------------------

Use two local players plus two bots, Carnage FX, rising lava and Full Works.
With one pad, verify P1 keyboard/mouse and P2 controller stay isolated. With
two pads, verify deterministic claims and no crossover. Separate humans so the
shared camera must frame both, then combine explosions, rope, rail, steampack
and barks. Look specifically for teleport, missed damage, debris towers, audio
dropout, stuck rumble, black camera edges, tick debt or a crash.

The release soak is 15 minutes and has explicit 5 ms average / 8 ms p95 /
16.67 ms maximum simulation targets on the named i7-10750H power-saver bench.
A five-minute quick soak is useful defect discovery but cannot pass that gate.

Workbook IDs: VOX-QA-014, 030, 037, 043, 065 and 084.


7. RETURN USEFUL FEEDBACK (2 MINUTES)
-------------------------------------

For each executed checkpoint select Pass, Fail, Blocked or Skip. Leave every
other row Not Run. For each distinct defect add one Issues row with checkpoint
ID, build/SHA, platform, exact seed/tick, controller/transport, minimal steps,
expected behavior, actual behavior and the smallest useful evidence path.

If xleak is installed, package the reviewed workbook and automation logs:

  ./qa-cockpit.sh --binary ./bin/digs_demo your-tester-copy.xlsx

The cockpit writes only under qa/out/ and uploads nothing. Review its report,
logs, screenshots and copied workbook for private information before sharing.


PLATFORM EVIDENCE BOUNDARY
--------------------------

Linux x86-64 is the only playable package in v0.0.3. The repository CI defines
modern Windows x64, macOS Intel and Linux i686 portable-core lanes with SDL/NASM
disabled where appropriate. Until a particular CI run is green, each lane is
only configured, not BUILDS or RUNS evidence. Even a green core lane does not
prove that platform's SDL window, audio, input, haptics, packaging or native
performance. DOS, Windows 3.x/9x/NT4/2000/XP, classic Mac, PowerPC, 68k and
period graphics/audio adapters remain planned adapter/lab targets requiring
QEMU, 86Box and eventually native-hardware evidence.
