# Third-party intake ledger

This ledger distinguishes code that the build actually links from projects
that are only design references. Every dependency must have compatible terms,
traceable provenance, and an explicit distribution decision before merge.

## Linked by the v0.0.1 demo

| Component | Use | License | Supported/tested version | Source | Intake and modifications |
|---|---|---|---|---|---|
| SDL2 | Optional desktop window, RGB texture presentation, input, timing, and queued audio | [zlib](https://github.com/libsdl-org/SDL/blob/SDL2/LICENSE.txt) | Floor: 2.0.10; tested: 2.30.0 | [upstream SDL2 branch](https://github.com/libsdl-org/SDL/tree/SDL2) | Found through CMake and linked from the host system; not vendored or modified |

The Free Software Foundation lists the
[zlib license as GPL-compatible](https://www.gnu.org/licenses/license-list.html#ZLib).
This repository does not distribute an SDL2 source tree or binary. A
downstream binary bundle that includes SDL2 must retain SDL's own copyright and
license notice and satisfy all applicable GPL Corresponding Source obligations
for VOX + DIGS.

SDL_ttf, SDL_mixer, SDL_image, SDL3, SDL_shadercross, and proprietary GPU SDKs
are not used by the `v0.0.1` build. The UI font, menu graphics, miner forms,
and short audio effects are generated by original repository code.

`GPL-3.0-or-later`. The assembler is not required for the default build and is
not a runtime dependency. The official project site states that NASM versions

## Intake requirements

Before adding or upgrading a dependency, a pull request must record:

1. exact upstream project and canonical source URL;
2. exact release, commit, and integrity hash when an artifact is downloaded;
3. license identifier, copyright notices, and GPL compatibility analysis;
4. whether it is system-linked, fetched for the build, vendored, or distributed;
5. local patches and generated-file provenance;
6. deterministic, platform, and maintenance impact; and
7. the notice, SBOM, and Corresponding Source changes required for a release.

Prefer a small system interface over importing a framework. Vendoring is an
evidence-based exception for platforms that cannot provide the dependency,
not the default dependency-management policy.
