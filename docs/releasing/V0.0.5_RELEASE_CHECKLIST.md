# v0.0.5 release checklist

"MEAT AND WEATHER" is not a partial feature-drop release. A public v0.0.5
tag is permitted only after the full roadmap scope and the carried v0.0.4
acceptance work are complete on the same frozen candidate.

Every box starts unchecked deliberately. A passing local command is evidence
for its stated lane, not evidence for a different machine, human interaction,
or public publication.

## Provenance and review

- [ ] The candidate is a clean reviewed commit on protected `main`; PR #9 and
  the release-foundation PR are merged normally with no force-push of `main` or
  a release tag.
- [ ] `VERSION` reads `0.0.5`; `tools/vox-version-check.sh`,
  `git diff --check`, and the generated `vox/vox_version.h` agree; the packaged
  title reads `DIGS v0.0.5`.
- [ ] The current branch topology, historical patch-equivalence audit, and
  Android disposition are recorded in `V0.0.5_BRANCH_AUDIT.md`.
- [ ] The annotated `archive/v0.0.4-phase2-stability` tag is present on the
  remote unchanged; it is visibly separate from a public release tag.
- [ ] No v0.0.4 candidate is retroactively tagged or published, and its
  original record remains intact per `V0.0.4_SUPERSESSION.md`.

## Full product scope

- [ ] Every Phase A–C requirement in `docs/ROADMAP_V0.0.5.md` has a completed
  implementation, a focused deterministic test where applicable, and a manual
  acceptance result. This includes connected-volume water/lava/blood behavior,
  damage-type dismemberment, bounded angular bodies and joints, support/load
  cluster collapse, weapon feedback, the always-toggle Steam Hook, dash,
  kill-heal, palette/provenance, presentation, and camera/animation work.
- [ ] Deferred-looking behavior is either completed or explicitly removed by a
  reviewed scope decision. A bounded internal substitute is not silently
  described as the requested large-world behavior.
- [ ] ABI 11, settings schema 6, chronicle format 1, and all readable schema
  migrations are independently verified. New match fields are explicitly
  initialized; `vox_digs_match_init` does not gain a blanket `memset`.
- [ ] Scalar, NASM, strict optimisation, and replay/hash gates agree on their
  canonical state. No port clock or presentation value reaches the canonical
  hash.
- [ ] Exact release-candidate counters, hashes, payload size, and performance
  figures are copied from that candidate's raw evidence only. Do not reuse a
  prior candidate's numbers.

## Automated and hosted gates

- [ ] A fresh Linux configure/build/test run completes with the repository's
  strict C89/C90 settings, native CTest, `tools/vox-verify.sh`, and
  `git diff --check`; complete exit statuses and output are retained.
- [ ] Linux x86-64 package preflight passes on the candidate and uploads only
  a `-ci` artifact. It must not create a public release.
- [ ] Windows x86-64 package preflight passes on the candidate and uploads only
  a `-ci` artifact. The package script consumes the checked-in
  `vcpkg.json`/`vcpkg-configuration.json` manifest and pinned baseline, not an
  unrecorded global SDL2 install.
- [ ] Linux, Windows x64, macOS Intel, and Linux i686 hosted checks are green
  for the exact candidate commit. Hosted success is not physical hardware
  acceptance.
- [ ] Any failed, timed-out, or cancelled check is diagnosed and rerun to a
  final observed result. A still-running process is not a pass.

## Release packages and reproducibility

- [ ] A clean Linux x86-64 bundle, Windows x86-64 ZIP, and Corresponding Source
  archive are built from the same immutable candidate. Each has an SPDX SBOM,
  notices, a SHA-256 record, and a captured compatibility/performance result.
- [ ] Freshly extracted Linux and Windows packages each run their actual
  executable's input and 600-tick load self-tests. The Linux bundle also runs
  its launcher, smoke test, and package evidence lane from its extracted tree.
- [ ] The Windows package is tested on a fresh Windows x64 environment rather
  than only from its build directory. Static SDL2 linkage, data lookup, and the
  `run-digs.bat` path are verified from the ZIP layout.
- [ ] The Linux package uses the documented system SDL2 runtime boundary and
  reports a missing runtime clearly. No local system file is copied into an
  archive by accident.
- [ ] The playable payload stays at or below 1,474,560 bytes. The source,
  notices, SBOM, evidence, and checksums are not counted as playable payload.

## Human acceptance

- [ ] The entire current QA workbook is regenerated deterministically and run
  against the frozen candidate. Any obsolete test semantics are revised before
  the run rather than marked pass by assumption.
- [ ] The carried v0.0.4 lane is complete on the v0.0.5 candidate, including
  VOX-QA-084 (fifteen-minute four-slot soak), VOX-QA-089–093 (memory and
  chronicle), and VOX-QA-096–100 (conversation pacing and interruption).
- [ ] Linux and Windows each receive a fresh-package manual run: launch,
  visible desktop, input, audio fallback/output, controller behavior where
  hardware is available, gameplay, shutdown, and evidence capture.
- [ ] New fluid, blood, anatomy, debris, collapse, grapple, dash, headshot,
  replay, and dropship scenarios are exercised by people and attached to the
  corresponding QA result. A self-test never substitutes for player-perceived
  behavior.
- [ ] Compatibility claims remain evidence-scoped. No claim about historical
  Windows, Android, GPU acceleration, a controller transport, audio hardware,
  or performance is inferred from an untested lane.

## Publish and retire safely

- [ ] The final clean commit receives an annotated `v0.0.5` tag only after all
  applicable checks above have passed. Never force-push that tag.
- [ ] `publish-release.yml` creates the public GitHub release with exactly the
  Linux x86-64 archive, Windows x86-64 ZIP, Corresponding Source, SHA256SUMS,
  and their SBOMs/notices; it refuses an accidental asset replacement.
- [ ] The public release is downloaded and its checksums, source correspondence,
  asset names, release notes, and tag target are independently verified.
- [ ] Only after public verification are Android PRs #7/#8 archived and stale
  local/remote refs pruned according to the branch audit. Do not use broad
  clean commands; preserve evidence and user-owned files.
